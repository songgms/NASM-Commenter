# NASM Commenter 功能全览

> 当前版本：v0.7.0 · 本文介绍扩展当前已实现的全部功能。
> 安装与开发环境见 [README](../README.md)，设计文档见 [00-index](./00-index.md)。

## 一、概述

NASM Commenter 是一个为 NASM 汇编（x86/x64）自动生成注释的 VSCode 扩展，采用 **LSP 双进程架构**（扩展宿主 + 独立语言服务器）。核心特点：

- **离线规则引擎为主**：91 条指令语义模板（中英双语）、9 种惯用模式、3 套 ABI 寄存器约定、336 条系统调用数据（Linux x64 157 / Linux x86 152 / macOS 27），全部数据驱动、可社区贡献
- **虚拟注释预览为默认工作方式**：注释先以幽灵文字展示、不改文档，确认后一键写入
- **LLM 为可选增强**：默认关闭，仅在规则引擎无法注释时介入，失败静默回退

## 二、工作流

```
打开 .asm 文件
  → 虚拟注释预览（幽灵文字，自动刷新，悬停看语义）
  → 满意后 Ctrl+; 写入当前行 / 命令写入整个文件
  → 维护：重复注释自动跳过（幂等）；按需移除或全部清除
```

## 三、虚拟注释预览（默认开启）

- 注释以 **Inlay Hint 幽灵文字**显示在行尾，**不修改文档**
- 编辑时自动刷新（按文档版本缓存，滚动/编辑不重复计算）
- **悬停幽灵文字**查看指令完整语义（类别、标志位、操作数形式）
- 已有真实注释的行不重复预览
- 命令 `切换虚拟注释预览` 或配置 `nasm-commenter.virtual` 开关；切换即时生效
- `%define` 常量在预览中按等值替换后的语义展示（如 `COUNT` → `3`）

## 四、注释写入

| 命令 | 快捷键 | 说明 |
|------|--------|------|
| 注释当前行 | `Ctrl+;` | 光标所在行 |
| 注释选中区域 | `Ctrl+Shift+;` | 选中范围内，对齐列统一 |
| 注释整个文件 | — | 幂等：已有相同注释的行自动跳过 |
| 注释当前函数 | — | 生成块注释（见下） |

- **两种样式**：`inline`（行尾，最小对齐列 `minColumn`，范围内自动对齐）/ `above`（行上方整行，缩进对齐）
- **幂等保护**：已写入相同注释的行跳过；默认保护用户手写注释（`protectExistingComments`，可关闭——关闭时新注释以 `旧注释 / 新注释` 追加）
- **详细模式**：`verbose` 开启后附加标志位与副作用说明
- **中英双语**：`language` 配置 zh/en，英文缺失时回落中文
- **置信度**：规则/模式/上下文增强固定 1.0；未收录指令生成兜底注释（0.3）并给出诊断提示

## 五、注释引擎能力

**数据驱动模板**：`mov`/`lea`/`add`/`cmp`/`jmp`/`syscall`/`db`… 共 91 条，模板按操作数签名（`reg,imm` 等）精确匹配，支持通配回落与条件片段（如 `xor rdi, rdi` → 「rdi 清零 (自身异或)」）。

**惯用模式识别**（优先于单行注释，整段成组）：

| 模式 | 效果 |
|------|------|
| 函数序言（push rbp / mov rbp,rsp / sub rsp,N） | 保存帧指针 / 设置帧指针 / 分配 N 字节局部空间 |
| 函数结尾（leave ret 或 mov/pop/ret） | 恢复栈帧 / 返回调用者 |
| write / exit 系统调用 | 逐行标注调用号与参数 |
| strlen 扫描（repne scasb） | 标注字符串长度计算 |
| 计数循环（mov / dec / jnz） | 初始化 / 递减 / 回跳 |

**上下文追踪**：

- 寄存器常量传播（`mov rax, 1` → 后续注释体现调用号；`add` 更新常量；`xor reg,reg` 清零）
- 别名处理：写 `eax` 同步更新 `rax`（反之写宽寄存器使子寄存器失效）
- 栈帧识别：`[rbp-N]` → 「局部变量 N」、`[rbp+N]` → 「函数参数 N」
- **系统调用参数回溯**：`syscall` 行生成「调用 write(1, msg, 13): 写文件」——调用号与参数值从上下文回溯
- `call` 后 caller-saved 寄存器失效；跳转目标处状态重置

**ABI 自动检测**：`int 0x80`/`bits 32` → Linux x86；`syscall` → Linux x64；`rax ≥ 0x2000000` → macOS（系统调用号自动归一）。可配置强制指定。

**函数块注释**（`注释当前函数`）：

```nasm
; 函数名: add_numbers
; 功能: 函数序言 (标准)
; 参数: rdi, rsi
; 返回: rax = 7
; 破坏的寄存器: eax, rbp
```

## 六、智能补全

- **命令位置**（行首/标签冒号后）：全部指令名，附中文语义与说明
- **操作数位置**：寄存器（附位宽）、本文档标签、`%define` 宏常量
- **跳转指令后**：标签优先排序
- **参数位置**：`section .` → 段名；`bits ` → 位数
- 前缀大小写不敏感过滤；注释内不触发

## 六点五、符号导航与格式化

- **转到定义 / 查找引用**：标签、%define 常量、宏、结构体字段
- **重命名**：单文档与已打开文档内批量重命名（F2）
- **文档大纲**：标签/函数/常量/宏一览
- **基础格式化**（format.enable）：标签顶格、助记符/操作数列对齐，注释文本原样保留

## 七、实时诊断（Problems 面板，打开/编辑时刷新）

| 诊断 | 级别 | 说明 |
|------|------|------|
| 未知指令 | Hint | 知识库未收录，将生成兜底注释 |
| 跳转目标未定义 | Warning | 如 `jmp nowhere` |
| 未引用标签 | Hint | 定义后全文未使用（豁免 `global` 导出与 `_start`） |
| 标签重复定义 | Warning | 同一标签多处定义 |
| 栈帧失衡 | Hint | rbp 序言后未发现恢复逻辑 |
| 寄存器无效赋值 | Hint | 刚写入即被覆盖且未读取 |
| 预处理嵌套不匹配 | Warning | %macro/%if 括号不闭合 |
| 内存-内存操作 | Hint | x86 不支持 mem-to-mem |

## 八、Hover 提示

| 悬停对象 | 内容 |
|----------|------|
| 指令名 | 语义、类别、标志位、操作数形式、注意事项 |
| 寄存器 | ABI 惯例角色（如 rax = 返回值/系统调用号） |
| 系统调用号（`mov rax, 60` 的立即数） | 调用名、参数、返回值 |
| `%define` 宏名 | 宏定义值 |

## 九、注释维护

| 命令 | 行为 |
|------|------|
| 移除自动注释 | 重新生成规则注释并与现有注释匹配：一致则删整段；`旧 / 新` 追加形式只剥离追加部分；above 样式删整行。LLM 增强的注释不参与（无法确定性重生成） |
| 去掉所有注释 | 清除文件内**全部**注释（含手写，模态确认）；整行注释删行、行尾注释剥离；字符串内 `;` 不受影响 |
| 切换行内/上方注释 | 样式即时切换 |

需要精确的标记式移除？配置 `marker` 为 `[nasm-commenter] ` 即可恢复标记模式（注释携带标记，逐行扫描移除）。

## 十、可选 LLM 增强

- 提供方：`openai`（任何 OpenAI 兼容端点：Azure OpenAI / DeepSeek / 通义千问等）/ `ollama`（本地模型）
- **触发时机**：仅当规则引擎无法注释（未收录指令）时调用；注释前请先配置 `apiKey`（Ollama 无需）
- **可靠性**：失败静默回退规则结果；结果缓存（避免重复请求）；请求超时可配
- **可观测**：请求延迟/失败/缓存命中日志写入输出面板（`NASM Commenter Server` 通道）
- 隐私：仅发送指令、操作数与前后 5 行上下文，不发送文件路径

## 十一、状态栏与输出面板

- 状态栏（右下）：`注释覆盖 X/Y 行 · ABI`，打开文件即显示，点击执行注释整个文件
- 输出面板：`NASM Commenter`（客户端日志）与 `NASM Commenter Server`（服务器日志、LLM 请求记录）
